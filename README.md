# x-follow-cleaner

[English](README.en.md) | 中文

X（推特）关注列表清理工具链。关注了几千个账号之后，真正的问题不是"删谁"，而是**"这个账号还值不值得留在我的信息流里"**。

核心立场：**取关不可撤销，所以误删比漏删严重得多。** 本项目的全部设计都围绕把误删率压到 0。

---

## 最省事用法：一键书签（推荐）

每次清理都要「打开 js → 全选 → 复制 → 粘贴进控制台」，而 Chrome 首次粘贴还会拦一道
"allow pasting"，要求你手动输入一遍。做成书签后：打开关注页 → 点一下书签 → 直接开跑。

```bash
python3 make_bookmarklet.py     # 生成 bookmarklet.html
```

打开生成的 `bookmarklet.html`，把页面上的两颗按钮**拖到书签栏**（`Cmd + Shift + B` 显示书签栏）：

| 书签 | 作用 |
|---|---|
| 预览（不删人） | `DRY_RUN=true` / `MIN_SCORE=40`，只列出该删的账号，一个都不动 |
| 执行（真删） | `DRY_RUN=false`，真正取关，跑满 50 个自动停 |

改配置不用改书签：编辑 `x_smart_unfollow.js` 的 `DRY_RUN` / `MIN_SCORE` / `WHITELIST`，
重跑一次 `make_bookmarklet.py` 即可同步。

> 为什么自带 minify：浏览器书签 URL 上限约 32KB，源码编码后会到 32.4KB 被**静默截断**。
> 压缩后 18.6KB（省 43%）。压缩器是状态机实现，能正确区分正则字面量 / 字符串 / 模板串，
> 不会压坏 `/(airdrop|加微信|...)/i` 这类词表 —— 已验证压缩前后 7 个样本打分完全一致。

python3 run_tests.py

| 验证 | 结果 |

| 规模压测（2000 个模拟账号） | 误删率 **0.00%**，垃圾号召回 **76.7%**，判定该删占 22.8% |

> 规模压测是模拟器，真实效果请以你导出的 `following_audit.json` 为准。

## 评分框架

按重要性排序：

1. **内容质量** —— 不能只看多久没发帖
2. **被有价值的人关注**的程度（社会证明 / 声望）
3. 是否涉及太多**推广 / 营销 / 诈骗**
4. 是否 **AI 化**
5. 是否**互关太多**
6. 是否**回关你** —— 最末位

分值含义：**分越高越该删，负分 = 建议保留**。默认阈值 20。

### 五项防误删设计（v3）

| # | 问题 | 修法 |
|---|---|---|
| A | `link in bio` / `linktr.ee` / `推广` / `带货` 正经创作者也用，一刀切 +35 会误杀 | 营销词**分级**：HARD（黑产/诈骗）+35，SOFT（商业化）+12 |
| B | "Crypto researcher, ex-JP Morgan" 被当成诈骗号删掉 | **可信身份豁免**：教授/记者/工程师/开源作者命中营销词时自动折减 70% |
| C | 2026 年蓝标 = 付费订阅，谁都能买，早已不是权威信号 | 蓝标**分级**：legacy/business/government −25，付费 blue 仅 −5 |
| D | 关注 3100 / 粉丝 900 的产品设计师被当互关党 | 互关比**双条件**：比值 + 绝对关注数，且分档 |
| E | 批量号没有明显关键词 | **handle 随机数字串**检测（5 位以上数字结尾） |

另外有一处刻意设计：**变质号识别**。最该删的往往不是垃圾号，而是"关注时是好号、后来变质的号" —— 老号、真粉丝、每个结构信号都正常，只有当前行为能暴露。普通工具里"老账号 −10"会把"营销 +35"抵消成 20 分待定，放走最该删的号。本引擎命中营销时取消老号加分，反追加「★老号变质」+10。

## 快速开始

**路径一：一步式（推荐）**

1. 打开 `https://x.com/<你的用户名>/following`
2. `Cmd+Option+J` 打开控制台，粘贴 `x_smart_unfollow.js` 全部内容回车
3. 默认 `DRY_RUN = true`，先看预览判定是否符合直觉
4. 认可后改 `DRY_RUN = false` 执行

顶部四个配置：

```js
const DRY_RUN  = true;    // 先预览
const MIN_SCORE = 20;     // 保守就调 40，只砍最恶劣的
const WHITELIST = [];     // 绝不动的 handle，优先级最高
const WEIGHTS   = {...};  // 框架归你：负数=保留，正数=该删
```

**路径二：报告路线（想慢慢挑）**

```bash
# 1. 浏览器跑 x_audit.js 导出 following_audit.json
# 2.（可选）跑 x_deepscan.js 补齐深度数据 → deepscan.json
# 3.
python3 x_score.py                 # 生成 following_report.html + unfollow_targets.txt
python3 x_score.py --selftest      # 先看引擎表现
```

## 安全（务必阅读）

- **每天 ≤100 个，分多天做，每批 ≤50。** 昨天手动删 200+ 大概率没事，但别连续高量。
- 脚本内置随机延迟 15–40 秒/次，模拟人类手速抖动，规避匀速检测。
- 断点续跑存在 localStorage，3000 个中断不用重来。
- 每次运行导出 `cleanup_log.json`，**误删可据此恢复**。
- X 的限制常是延迟生效，出现"操作受限"提示立即停 48 小时。

## 与竞品的差异

对标 Circleboom（Trustpilot 2.2/5）、Fedica、各类浏览器扩展。

做得比它们好的：
- **可解释**：每条判定打印分数 + 原因。Circleboom 被大量用户投诉"未回关列表 90% 是误判，导致误删" —— 黑盒的原罪。
- **权重开放**：`WEIGHTS` 全开放可调。竞品的判定标准你改不了。
- **误删率可量化**：`benchmark.py` 直接给出对照证据。
- **零成本、零数据外传**：纯本地运行，不需要 OAuth 授权任何第三方。

不如它们的地方（诚实说）：
- **执行安全性**：Circleboom 走官方 API 被 X 认可；本项目是浏览器脚本模拟点击，本质更危险，只能靠延迟和分批缓解。
- **UI**：它们是成熟 SaaS 仪表盘，本项目是脚本 + HTML 报告。

## 已知局限

- 框架 1（内容质量）和框架 2（被谁关注）的**最终判断只能靠人眼**。脚本做的是第一关过滤，剩下的"互关的真实人"里挑，抽看 20 个比自动抓 2000 个信息量大。
- following 列表页本身看不到粉丝数/关注数/认证类型，需要 `x_deepscan.js` 补。数据完整度低于 60% 时报告会明确提示。
- 关键词表偏向中英文常见黑话，其他语种需自行补充 `keywords.json`。

## 自定义

同目录放 `keywords.json`：

```json
{
  "spam": ["你们行业的黑话", "某资金盘名"],
  "keep": ["同行名", "必须保留的机构"]
}
```

调权重直接改 `WEIGHTS`。改完跑 `python3 run_tests.py` 确认没有把误删率抬上去。
